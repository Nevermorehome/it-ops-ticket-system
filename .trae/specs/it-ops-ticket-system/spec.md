# 信息部内部 IT 运维工单记录系统 - 产品需求规格说明书

## Overview
- **Summary**: 面向企事业单位信息部门的内部 IT 运维工单系统，覆盖"报修 → 派单 → 现场处理 → 解决关闭 → 统计分析"全流程，提供 Web 管理后台、移动端 H5（可打包 Android APK）两端，以及容器化部署方案。
- **Purpose**: 替代纸质/群聊报修方式，实现工单全生命周期可追溯、现场处理有据可查（定位+拍照水印）、运维工作量可量化统计、消息通知及时触达。
- **Target Users**:
  - **报修人**（普通员工）：移动端提交报修、查看进度、评价/确认。
  - **运维工程师**：移动端受理、挂起、现场记录（GPS+拍照水印）、填报解决方案。
  - **调度/主管**：Web 端派单、转派、协同人指派、合并工单、监控处理时效。
  - **系统管理员**：用户/角色/菜单/部门/字典/地点/日志/配置等系统管理。
  - **部门领导**：查看本部门工单与统计报表。

## Goals
- 工单全生命周期线上化：创建、编辑、指派、转派、协同、受理、处理、挂起、恢复、解决、关闭、重开、取消、合并共 14 类操作全部有状态机校验、权限校验与时间线留痕。
- 现场处理可信留证：自动记录时间、GPS 定位、地图选点、拍照/相册多图上传、客户端压缩、图片水印（时间+地点+经纬度+操作人）。
- 数据驱动：日报/周报/月报/自定义时间段统计，支持导出 Excel/PDF/Word。
- 多端触达：站内信、H5 站内消息、APP 推送（UniPush 预留）、企业微信/钉钉/飞书群机器人 Webhook。
- 一套 docker-compose 完成 MySQL + 后端 + 管理后台/H5 静态资源 + Nginx 反向代理的整体部署。

## Non-Goals
- 不实现真实第三方应用市场上架、不代签 Android APK；交付可被 HBuilderX/CLI 打包的 UniApp 工程源码与打包说明。
- 不实现 ITIL 全套流程（变更/发布/问题管理/CMDB 全量模型）；仅做事件类工单与资产关联。
- 不实现 SLA 自动计费、配件库存、收费结算（可在后续迭代扩展）。
- 不内置真实地图厂商 Key；地图选点使用 UniApp `chooseLocation`（腾讯/高德 Key 可配置），后台管理以经纬度字段为准。
- 不做微服务拆分，单体 Spring Boot 应用即可满足内部系统规模。

## Background & Context
- 工作目录 `d:\worklog` 当前为空，全新工程，采用 Monorepo 三端 + 部署目录组织。
- 参考既往同类项目经验：采用标准 Spring Boot 官方目录结构；不修改全局 Maven 配置；Windows 环境路径与脚本兼容性需注意。
- 内部系统部署于内网，文件存储默认使用服务器本地磁盘（通过 Nginx/后端静态映射），保留 MinIO/OSS 扩展点。

## Functional Requirements

### FR-1 认证与会话
- 用户名+密码登录，密码 BCrypt 存储；登录成功签发 JWT（accessToken），前端请求头 `Authorization: Bearer xxx`。
- 支持获取当前用户信息（含角色、权限标识、动态菜单）、修改密码、退出登录（服务端可维护 token 版本/黑名单，最小实现以 JWT 无状态为准）。
- 登录日志记录（IP、浏览器、时间、成功/失败）。

### FR-2 用户、部门、角色、菜单、数据权限
- 用户管理：分页查询、新增、编辑、删除、重置密码、启用/停用、分配角色；用户归属部门。
- 部门管理：树形 CRUD。
- 角色管理：CRUD、分配菜单权限、分配数据范围（全部数据 / 本部门 / 本部门及以下部门 / 仅本人）。
- 菜单管理：树形 CRUD，目录/菜单/按钮三类，含路由路径、组件、权限标识（如 `ticket:assign`）、图标、排序。
- 数据权限：列表查询按角色数据范围自动过滤（部门维度 + 创建人/处理人维度）。

### FR-3 工单管理（核心）
- **创建**：报修人或工程师代客创建；自动生成工单编号（规则如 `WO20260925001`）。字段：编号、标题、分类（树形字典）、问题描述、报修人、部门、电话、来源（电话/微信/现场/自助/其他-字典）、优先级（低/中/高/紧急）、状态、地点、经纬度、关联资产、处理人、协同人（多人）、时间线、处理情况、解决方案、附件图片。
- **编辑**：待处理前可编辑基本信息；已流转后受字段级权限控制。
- **列表/详情**：多条件分页筛选（编号/标题模糊、分类、状态、优先级、部门、处理人、报修人、时间范围）；详情返回主信息+时间线+协同人+附件+现场记录。
- **指派**：调度/主管指定主处理人，状态 → 已指派。
- **转派**：当前处理人或主管改派他人，记录转派原因，时间线留痕。
- **协同**：增删协同人，协同人可见该工单并可添加处理记录。
- **受理**：处理人接单，状态 → 处理中。
- **处理**：多次追加处理情况（文字+图片），时间线逐条留痕。
- **挂起/恢复**：处理中可挂起（必填挂起原因，如等待备件/等待用户），可恢复。
- **解决**：填写解决方案，状态 → 已解决。
- **关闭**：报修人确认或主管关闭，状态 → 已关闭。
- **重开**：已关闭工单在允许期限内可由报修人/主管重开，状态 → 处理中，时间线留痕。
- **取消**：未受理前允许报修人/主管取消。
- **合并**：主管选择多张同类工单合并到目标工单，被合并单置为"已合并"并指向目标单，后续只在目标单流转。
- 所有动作校验：当前状态是否允许该动作、操作人是否有权限（角色权限标识 / 是否处理人或协同人或报修人），非法操作返回明确错误。

### FR-4 现场记录（移动端重点）
- 工单详情中可新增多条现场记录：自动带入服务器时间、GPS 经纬度（uni.getLocation，gcj02）、支持地图选点（uni.chooseLocation）回填地点与经纬度。
- 拍照/相册多图选择（uni.chooseImage/chooseMedia，最多 9 张/条）、`uni.compressImage` 客户端压缩。
- 图片水印：Canvas 合成时间、地点、经纬度、操作人信息后上传。
- 上传走统一文件接口，返回 URL；现场记录与图片关联保存。
- 工单创建时也支持附带定位与图片。

### FR-5 报表统计
- 维度：按日/周/月/自定义时间段；按处理人、分类、部门、优先级、状态、来源统计工单数、解决数、平均处理时长、超时/挂起情况。
- Web 端 ECharts 展示：趋势折线/柱状、分类占比饼图、处理人排行。
- 导出：Excel（EasyExcel）、Word（POI XWPF，含汇总表格）、PDF（HTML 模板转 PDF，含中文字体）。
- 日报/周报/月报支持一键按区间生成。

### FR-6 消息通知
- 站内信：关键动作（被指派、被转派、被加协同、工单解决/关闭/重开）生成站内消息，已读/未读、未读数、全部标记已读。
- APP/H5：H5 轮询/手动拉取未读数；预留 UniPush 推送接入位（配置项）。
- Webhook：可配置企业微信/钉钉/飞书群机器人地址与启用开关，关键事件按模板推送，含工单标题、编号、状态、链接、操作人。

### FR-7 系统管理
- 字典管理：字典类型与字典数据 CRUD（工单来源、优先级、挂起原因等）。
- 地点管理：常用地点维护（名称、楼栋楼层、经纬度），创建工单时可快速选择。
- 资产管理：资产编号、名称、类别、使用人、部门、位置、状态，工单可关联资产。
- 操作日志：AOP 记录关键写操作（人、时间、方法、参数摘要、IP）。
- 系统配置：键值对参数（如 webhook、附件大小限制、水印开关）。
- 备份：提供数据库备份说明/脚本（mysqldump 定时任务示例），不在应用内执行危险命令。

### FR-8 多端形态
- **Web 管理后台**：Vue3+Vite+TS+Element Plus+ECharts，登录/布局/动态路由/按钮权限指令。
- **移动端 H5**：UniApp+Vue3+TS+Pinia，兼容 H5 与 App（Android）；uView Plus（通过 uni_modules/npm 安装，组件按需）；核心页面：登录、工单列表（我报修的/待我处理/我协同的/全部 Tab）、创建工单、工单详情与操作、现场记录、消息列表、我的。
- **Android APK**：UniApp 工程可在 HBuilderX 中云打包/本地打包为 APK（提供 manifest 配置与打包说明文档）。

## Non-Functional Requirements
- **NFR-1 可部署性**：提供 docker-compose.yml 与 Dockerfile，宿主机安装 Docker 后一条命令启动全套；首次启动自动建表并初始化管理员与基础字典/菜单数据。
- **NFR-2 安全**：密码 BCrypt；接口鉴权 + 细粒度权限标识；SQL 注入由 MyBatis-Plus 参数绑定防护；上传文件类型/大小校验；CORS 白名单。
- **NFR-3 可移植性**：JDK 17、MySQL 8、Node 18+；前后端配置（数据库口令、API 基址、地图 Key）集中在配置文件/环境变量。
- **NFR-4 性能**：列表分页必做；工单列表常用查询字段建索引；附件上传大小限制可配置（默认单图 10MB）。
- **NFR-5 可观测**：统一异常处理与统一响应结构 `{code,msg,data}`；后端结构化日志；Knife4j/OpenAPI 接口文档。
- **NFR-6 兼容性**：移动端 H5 适配主流手机浏览器；管理后台适配 Chrome/Edge 最新两个大版本。
- **NFR-7 中文**：全系统界面、导出文件、水印时间均使用中文/中文时区（Asia/Shanghai）。

## Constraints
- **Technical**：后端必须为 Spring Boot 3 + Spring Security + JWT + MyBatis-Plus + MySQL 8；Web 必须为 Vue3 + Vite + TS + Element Plus + ECharts；移动端必须为 UniApp + Vue3 + TS + Pinia；部署必须为 Docker Compose + Nginx。
- **Business**：内网内部系统，账号由管理员创建，不开放公开注册。
- **Dependencies**：地图与推送依赖第三方 Key（部署时配置）；webhook 依赖企业 IM 群机器人。
- **环境约束（Windows 开发）**：所有脚本提供跨平台写法；不改写全局 Maven/Gradle 配置；构建验证以本机已安装工具链为准，缺失工具时在文档中说明。

## Assumptions
- 初始管理员账号 `admin / admin123`（首次登录提示改密为非阻塞功能，种子数据保证可登录）。
- 地图坐标系使用国测局 gcj02；H5 地图 Key 在 `.env` / manifest 中配置，未配置时地图选点按钮提示但不阻塞手工输入地点与经纬度。
- 附件本地存储目录为后端容器内 `/data/uploads`，由 Nginx 或后端 `/uploads/**` 映射对外。
- 移动端 UI 组件以 uView Plus 为主（npm 依赖），缺失的复合组件用原生/uni-ui 自绘，不强依赖商业插件。
- 报表导出的 PDF 中文字体使用容器内可用的开源中文字体（Noto Sans CSC），后端资源目录内置一份字体或文档给出挂载方式。
- 工单状态固定为：待受理(DRAFT/PENDING)、已指派(ASSIGNED)、处理中(PROCESSING)、已挂起(SUSPENDED)、已解决(RESOLVED)、已关闭(CLOSED)、已取消(CANCELLED)、已合并(MERGED)。

## Acceptance Criteria

### AC-1：容器化一键部署可用
- **Type**: `rule`
- **Given**: 已安装 Docker 与 Docker Compose 的干净环境
- **When**: 在 deploy 目录执行 `docker compose up -d` 并等待初始化完成
- **Then**: MySQL 8 启动并自动执行初始化 SQL；后端容器健康（健康检查接口 200）；Nginx 能同时提供 Web 后台、H5 静态资源并反代 `/api`
- **Pass Condition**: 浏览器访问 Web 后台地址出现登录页；使用 admin/admin123 登录成功；H5 地址可打开登录页
- **Evidence**: docker compose 配置、初始化 SQL、Nginx 配置、README 部署步骤；如本机具备 Docker 则附实际启动验证输出

### AC-2：认证与接口安全生效
- **Type**: `rule`
- **Given**: 系统正常运行
- **When**: 未携带 token 访问受保护接口；携带错误/过期 token 访问；携带合法 token 但调用无权限标识的接口
- **Then**: 分别返回 401、401、403；登录成功返回 JWT 且可通过 `/auth/info` 换取用户、角色、权限、菜单
- **Pass Condition**: 三类拒绝行为均可观测，且密码在数据库不以明文存储
- **Evidence**: Spring Security 配置、JWT 过滤器、接口注解；接口工具/curl 验证结果

### AC-3：RBAC 与数据权限正确
- **Type**: `rule`
- **Given**: 构造部门树与至少三种数据范围角色的用户
- **When**: 不同用户查询工单/用户等列表
- **Then**: "全部数据"可见全部；"本部门及以下"仅见本部门与下级部门数据；"仅本人"仅见创建人或处理人是自己的数据
- **Pass Condition**: 三种范围返回结果集互有差异且与规则一致；菜单/按钮权限按角色显隐
- **Evidence**: 数据权限切面/SQL 拼接实现、种子用户脚本、验证 SQL/接口结果

### AC-4：工单状态机 14 类操作全部受控
- **Type**: `rule`
- **Given**: 各类状态的工单与不同角色用户
- **When**: 依次执行创建、编辑、指派、转派、协同、受理、处理、挂起、恢复、解决、关闭、重开、取消、合并
- **Then**: 合法流转成功且每条动作写入时间线（操作人、动作、时间、备注）；非法流转（如待受理直接解决、已关闭再挂起）返回业务错误；越权操作（非处理人受理）返回 403/业务错误
- **Pass Condition**: 合法路径全部成功、至少 3 条非法路径被拒绝、被合并单指向目标单且不可再独立流转
- **Evidence**: 状态机枚举与流转校验代码、时间线表数据、接口验证记录

### AC-5：工单完整字段可持久化与回显
- **Type**: `rule`
- **Given**: 包含全部要求字段（含多附件、多协同人、地点经纬度、资产）的创建请求
- **When**: 创建后查询详情
- **Then**: 编号自动生成且唯一，其余字段与入参一致，附件与协同人正确关联并回显
- **Pass Condition**: 需求列明的全部字段在库表与详情接口中均存在且值正确
- **Evidence**: 建表 DDL、实体/VO、详情接口返回样例

### AC-6：移动端现场记录能力完整
- **Type**: `rule`
- **Given**: 工程师在工单详情中新增现场记录
- **When**: 授权定位后获取 GPS，地图选点回填，拍照/相册选择多张图片，执行压缩与水印合成后提交
- **Then**: 记录保存服务器接收时间；经纬度/地址与图片 URL 落库；图片上肉眼可见含时间、地点、经纬度、操作人水印；离线/拒绝授权时给出明确提示且可手工填写
- **Pass Condition**: 真机或浏览器 H5 可完成一次完整现场记录提交，后端可查到记录与图片；水印四要素齐全
- **Evidence**: 移动端现场记录页面代码、水印 canvas 工具代码、接口数据截图/记录

### AC-7：现场记录交互体验
- **Type**: `rubric`
- **Dimension**: 移动端现场记录流程的易用性与可靠性
- **Scale**: 1-5
- **Anchors**: 1 = 无法完成拍照定位上传；3 = 功能可用但步骤繁琐、异常无提示；5 = 三步内完成、自动定位压缩、异常均有中文提示、图片可预览删除
- **Pass Threshold**: >= 4
- **Evidence**: H5 实际操作走查记录

### AC-8：报表统计与三类导出
- **Type**: `rule`
- **Given**: 跨多个状态与日期的工单数据集
- **When**: Web 端选择日/周/月/自定义区间查询统计并分别导出 Excel、Word、PDF
- **Then**: 返回正确 MIME 类型的文件；文件可被 Office/WPS/PDF 阅读器打开；含区间、汇总数字、明细/图表要素；PDF 中文不乱码
- **Pass Condition**: 三种格式文件均下载成功且内容正确；图表页展示趋势/占比/排行
- **Evidence**: 报表接口、导出实现、实际导出的文件验证记录

### AC-9：消息通知与 Webhook
- **Type**: `rule`
- **Given**: 配置好的企微/钉钉/飞书任一 webhook 地址并启用；有两个测试用户
- **When**: 执行指派、解决、关闭等关键动作
- **Then**: 对应用户站内信生成且未读数增加；webhook 平台收到格式正确的消息卡片（含编号、标题、状态、链接）；关闭开关后不推送
- **Pass Condition**: 站内信与 webhook 双通道行为均可观测，开关生效
- **Evidence**: 消息服务代码、webhook 报文样例/联调记录

### AC-10：Web 管理后台功能完整性与体验
- **Type**: `rubric`
- **Dimension**: 后台覆盖度与交互质量
- **Scale**: 1-5
- **Anchors**: 1 = 仅登录页可看；3 = 主要列表页可用但布局粗糙、按钮权限缺失；5 = 系统管理/工单/报表/消息各模块页面齐全、动态菜单与按钮权限生效、查询分页操作反馈完整、风格统一
- **Pass Threshold**: >= 4
- **Evidence**: 页面清单、浏览器走查记录

### AC-11：移动端功能完整性
- **Type**: `rubric`
- **Dimension**: H5/App 端业务覆盖度
- **Scale**: 1-5
- **Anchors**: 1 = 仅登录；3 = 可建工单和看列表，处理动作缺失；5 = 登录、四 Tab 列表、建单（含图/定位）、详情全部 14 类可用操作、现场记录、消息、我的均可用
- **Pass Threshold**: >= 4
- **Evidence**: 页面与 API 调用清单、H5 走查记录

### AC-12：工程质量与可维护性
- **Type**: `rubric`
- **Dimension**: 代码规范、结构清晰度、文档完备度
- **Scale**: 1-5
